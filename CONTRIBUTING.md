# Contributing to XML and Modern Web Services

Thank you for your interest in contributing! This is a learning resource built by students, for students. We welcome contributions from classmates and the community.

## How to Contribute

### Reporting Issues

- Found a bug or unclear explanation? Open an issue
- Include what week/section you're in
- Describe what's confusing or broken
- Share your OS and Node/Python version if relevant

### Suggesting Improvements

- Have a better explanation for a concept?
- Know a clearer code example?
- Found a helpful resource to add?
- Open an issue with the `enhancement` label and describe your idea

### Adding Content

We're open to:

- **Corrections** - Fix typos, errors, or outdated information
- **Code improvements** - Clearer examples, better comments
- **New examples** - Additional working code for a week's topic
- **Resources** - Links to helpful tutorials or documentation
- **Exercises** - Practice problems with solutions

## Getting Started

1. Fork the repository
2. Create a feature branch: `git checkout -b feature/your-improvement`
3. Make your changes following the guidelines below
4. Test your code (if adding examples)
5. Commit with clear messages: `git commit -m "Add: GraphQL query example for week 11"`
6. Push to your fork and open a Pull Request

## Guidelines

### Code Examples

- Include comments explaining what the code does
- Test that it actually runs (Node.js or Python as relevant)
- Keep examples focused and not overly complex
- Use consistent formatting with existing code

### Explanations and Documentation

- Use clear, student-friendly language
- Avoid jargon without explanation
- Include "why" not just "how"
- Link to relevant resources

### Commit Messages

Use clear, descriptive commits:

- Incorrect: "fix stuff"
- Correct: "Fix: correct XPath example in week 03"
- Correct: "Add: JWT authentication code example for week 12"

### File Organization

- Follow the existing week-by-week structure
- Place code examples in the `examples/` folder
- Place exercises in the `exercises/` folder
- Update the relevant week's README.md

## Pull Request Process

1. Update documentation if needed
2. Test your changes
3. Reference any related issues: "Closes #123"
4. Describe what you changed and why
5. Be open to feedback and suggestions

## Code of Conduct

- Be respectful and constructive
- Help each other learn
- Maintain a professional and inclusive environment
- Focus on making this resource better for everyone

## Questions

- Check existing issues for answers
- Open a discussion if unsure
- Reach out to the maintainers

Thank you for contributing to this learning resource.
